# ML methodology and measured limitations

Isolation Forest is an optional investigation lens. Deterministic rules remain the default. No model score is a probability of compromise or a confirmed malicious event.

## Reproducible training

- Four separately generated benign baseline datasets, seeds **17, 29, 43, 61**, 480 events each: **1,920 training events**.
- Isolation Forest: **160 estimators**, `max_samples=256`, `contamination=0.025`, `random_state=42`, `n_jobs=1`.
- Training is cached in process memory and first-time training is serialized. No uploaded models, pickle files or user-supplied code are loaded. Restarting a worker deterministically retrains from the same generator and dependency lock.
- Model labels, event IDs, source-IP strings, usernames, free text and input severity are excluded from numeric features.

## Features

| Feature | Definition / interpretation |
| --- | --- |
| `hour_sin`, `hour_cos` | Cyclic encoding of UTC hour including minutes |
| `off_hours` | 1 outside the example 06:00–22:00 UTC business window |
| `is_login` | 1 for a login action |
| `is_failure` | 1 for a failure outcome |
| `log_bytes_sent` | `log(1 + bytes_sent)` reduces volume scale |
| `source_events_60s` | Current and preceding events from the same IP in an inclusive 60-second window |
| `source_failures_300s` | Current and preceding failed logins from the same IP in an inclusive 300-second window |

Events sort by timestamp and ID. Rolling counts are causal: later events cannot alter earlier feature rows. Each training dataset is engineered independently before concatenation so rolling history does not leak between datasets. Isolation Forest does not need standard scaling. Feature distributions still reflect this synthetic generator and can differ sharply from authorized real logs.

## Scoring and feature context

The displayed score is the negative of scikit-learn's `decision_function`; **higher is more unusual**, and **positive** scores cross the fixed model threshold. Scores are not normalized confidence percentages. The UI returns at most the 30 highest positive-score candidates while preserving the total candidate count.

For context, the UI shows three feature values with the largest absolute deviation from the training median divided by training IQR, with IQR floored at 1. These values explain differences from the baseline, **not** causal feature attribution inside the trees. A large feature difference does not establish why a particular tree classified an event.

## Actual held-out evaluation

The checked-in [machine-readable artifact](ml-evaluation.json) is generated by the running implementation, not estimated or hand-entered. Protocol: all five scenarios at held-out seeds **101, 203, 307**, producing **15 datasets**, **7,482 events** and **282 suspicious labels**. Training and test seeds are disjoint; the model threshold is fixed before evaluation. Within each seed, scenario variants deliberately reuse the same benign background, enabling paired comparison but introducing correlation. These are not 7,482 statistically independent observations.

| Method | Precision | Recall | F1 | True negatives | False positives | False negatives | True positives |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| Deterministic rules | 1.000000 | 1.000000 | 1.000000 | 7,200 | 0 | 0 | 282 |
| Isolation Forest | 0.252874 | 0.234043 | 0.243094 | 7,005 | 195 | 216 | 66 |

The synthetic suspicious labels intentionally match the four demonstration rules, so perfect rule results are optimistic by construction. They do not estimate operational efficacy. The ML baseline is intentionally simple, produces substantial false positives, and misses many labeled events. It is not a replacement for rules or a validated production classifier. No confidence interval or real-world accuracy claim is made.

Metrics are **event-level**: a rule predicts suspicious for each event referenced by any alert; the ML prediction is a positive anomaly score. The confusion matrix has actual benign/suspicious rows and predicted benign/suspicious columns. This is different from measuring alert-level incident precision.

## Reproduce

From the repository root on PowerShell:

```powershell
$env:PYTHONPATH = 'backend'
uv run python -m threatscope.ml.evaluate
```

On macOS/Linux: `PYTHONPATH=backend uv run python -m threatscope.ml.evaluate`.

Use `uv sync --frozen` first. The JSON records the scikit-learn version; dependency upgrades can change results and must regenerate/review the artifact. CI checks for drift. Broader deployment requires authorized labeled logs, representative temporal/entity splits, account-specific policy tuning, drift monitoring and human review; those capabilities are outside this release.
